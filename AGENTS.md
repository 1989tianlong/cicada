# AGENTS.md

Cicada (知了, formerly Live Subs) is a macOS menu bar app that turns whatever the Mac is playing (streams, videos, meetings, voice rooms) into live translated subtitles, keeps every meeting as a bilingual transcript, and can translate what you say back into the room as speech.

## Scope (deliberately small)

- Few surfaces, nothing more: the **menu bar panel** (on/off, heard language, translate-to language, "同声传译", display mode, an update strip when a newer release is out, meeting records, quit), what shows while listening — the **live notes window** (default) or the **subtitle bar** or nothing (`displayMode`) —, the **main window** (meeting records) and a **settings window** (sidebar: 显示 / 语言 (`LanguageSettings`: heard language, 字幕 both/translation/original, translate-to, notes language mine/source, speak-back pair, under a route line) / 同声传译 / 通用 (meeting audio, records folder, 登录时打开, version + 检查更新, onboarding; `SettingsSection.records`) / AI 服务, plus 诊断 when the bottom-left switch is on). First launch shows a three-step **onboarding** window (permissions, try the sample video, speaking).
- Listening: system audio (Core Audio process tap, our own process excluded) → spoken-language detection across installed on-device models → on-device transcription (`SpeechAnalyzer` / `SpeechTranscriber`) → translation → notes window caption or subtitle bar. Every confirmed sentence goes into the live meeting record. Translation (`TranslationService`): finished sentences and speak-back go to Ling when a key is set (glossary from the notes' terms), else or on any failure Google, then Apple's on-device `TranslationSession(installedSource:)`; partial text refreshed every second always goes to Google (it would use up Ling's rate limit).
- Language detection compares confidence: the same 3–6 s clip after a pause is transcribed by every installed model; a winner needs confidence ≥ 0.6 and a 0.08 lead; the first detection or a 0.30 lead switches at once, otherwise two agreeing detections. After a switch the last 8 s are replayed into the new model.
- "Follow system" translates into the first system language that differs from the source language.
- Subtitle bar: shows only while someone talks (auto) or always; tucks into a dot after 2/4/8 s of quiet; fades to 15% and stays click-through while the pointer passes over it; editable after the pointer rests 0.6 s (drag to move, drag the corner to scale, double-click resets); ⌃⌥S (changeable) cycles the display mode (notes → bar → none). Position, width and size are remembered per display.
- Speaking: hold the right ⌥ key alone (a listen-only event tap, needs Input Monitoring; any other key while held cancels the press as a chord) or a user-chosen combination (Carbon hotkey, no permission) → microphone → with a usable Ling key the press (16 kHz WAV, ≤ 60 s) goes to `Ming-3.0-audio-flash` in one `.speak` request that returns `ORIGINAL:` / `TRANSLATION:` lines (`TranslationService.interpret`; anything else is dropped, since the model sometimes answers a question instead of interpreting it; ~2 s, names right). One `SpeechAnalyzer` per press always runs too, finished with `finalizeAndFinishThroughEndOfInput`: it shows the words while held and is the fallback transcript, translated into the room's language by the usual chain → voice → the chosen output device (a virtual microphone). The virtual microphone is BlackHole 2ch, installed from the app: download the official notarized package, check its pinned SHA-256, run `installer` and restart `coreaudiod` in one standard administrator prompt (the package only copies the driver and asks for a reboot; Core Audio loads a new HAL plug-in only when it restarts). Then a loopback sound test: speak a fixed English phrase into the device, record its input side, transcribe it (`LoopbackTest`). The checklist UI (`MicSetupCard`) is shared by onboarding step 3 and settings. We never bundle the GPL driver.
- AI (Ling, ant-ling.com, OpenAI-compatible): one user key for the whole app, for now in a 0600 file `ling-api-key` in the app's Application Support folder, excluded from backups (`AIKey`; never in UserDefaults, logs or exports; ad-hoc signing makes the Keychain ask for the password after every rebuild or update, so it moves back to the Keychain once builds have a Developer ID; a key in the old Keychain item, service = bundle id + `.ai`, is moved over once), checked with a one-token `Ling-3.0-tiny` call. `LingClient` is the single gate for every call: request *starts* ≥ 0.6 s apart (the account allows ~2 requests/s across all models), waiting requests ordered speak-back > translation > notes; notes retry 429 with 1/2/4/8 s backoff, translation and speak-back fail fast to the next translator; 401 marks the key invalid. Every call sends `thinking: disabled`, puts the content in the **system** message and a fixed instruction in the user message (otherwise question-like text gets a search-grounded essay instead), and drops replies with no `finish_reason` or starting 根据现有检索证据.
- Live notes (`NotesEngine`, UI-free): about every 45 s with new lines, one JSON call sends the current notes + new lines (`[L12 02:03 对方] …`) and gets the whole notes back (a meeting name — shown as "<date> <name>" via `Session.displayTitle` unless the user renamed it —, summary, ≤ 8 topics with points and an optional fishbone, conclusions/to-dos with evidence line ids → support counts, terms with misrecognised forms); a bad reply never replaces good notes. A final pass over the whole transcript runs when the meeting ends ("完整版"). Notes are written in the 纪要语言 (`AppModel.notesLanguageCode`): the reader's language by default (the translate-to choice, or Chinese when Chinese is among the system languages), or the meeting's own; one meeting can differ (`notesLanguageFor`, the notes window's "EN → 中" chip, an inline card since a popover closes at once in the non-activating panel; changing it mid-meeting rewrites the notes from scratch, `NotesEngine.rewrite`). The language is stated again at the end of the prompt and in the user message, and a reply not in it (`NotesEngine.written`, CJK share) is retried once on the final pass, otherwise dropped: the final pass has no Chinese notes to follow, and a long English transcript pulls it into English. Stored as `notes` in `session.json`; finished meetings without notes can generate them from the main window. Speak-back voices (`Voices.swift`, settings UI `VoicePicker.swift` on the 同声传译 page): one choice per room language (`speakVoices`, "en" → `ming:US_Emma` / `system:<AVSpeechSynthesisVoice id>` / `clone`). Offered: hand-picked Ming voices (English Emma/George/Charlotte; Chinese 小雅/小棠/小锋/卓然; ja/ko/de/fr/es via Emma/George with `language_id`) and the Mac's best female and male voice; default is Ming's first with a key, else the Mac's. `clone` is the user's own voice: a 8–30 s recording read from a passage in their language (16 kHz WAV + its on-device transcript in `voice/` under Application Support, 0600, out of backups), sent to Ming as `references` with every sentence (~600 KB, first audio ~3 s, ~8 s on a cold call; a foreign language keeps the speaker's accent). Ming's voices fall back to the Mac's voice without a usable key or when the stream fails; previews play on the default output, not the room.0-tts-0.5B`, SSE PCM 24 kHz) through the same key, falling back to the system voice.
- Live notes window (`NotesWindow`): opens at the first words of a meeting (system audio or a talk press; `AppModel.heardSpeech`), or at once when the user picks it; a floating `NSPanel`, `sharingType = .none` (invisible to screen sharing and screenshots), on all Spaces, frame autosaved; < 360 px a card that offers what the notes added since it was collapsed ("收起后新增 …", only when there is something), tabs 纪要 / 文字记录 in between, both side by side from 760 px; a 结束 button while live (asks in an inline strip once there are lines; `AppModel.requestStop` asks with an alert for ⌘R and the panel switch, 继续记录 the default), then an ended strip (final-pass state, 在会议记录中查看, 开始新会议); `FirstClickHostingView` so a click works without focusing the panel first; banners for no key (inline key entry) / invalid key / rate limited. While writing: sound bars before anyone speaks, a spinner with "已听到 N 句" and shimmering placeholders for the first version, an "正在更新" pill and a warm shimmer under the current topic for later updates (`TimelineView`, since the window redraws every second). Transcript: oldest first, follows the newest line plus the sentence still being spoken; following survives content and window height changes, and only a real scroll-wheel/trackpad event (`UserScroll`) followed by scrolling up pauses it and gathers new lines into a "↓ N 句新内容" button; search highlights in place (query plus the notes' misheard forms of a name). Notes carry times: points and conclusions get the time of their first evidence line (`pointTimes`, `NoteItem.t`; carried over when the model echoes a point without evidence), topics show ranges.
- App menu (`AppMenu`): the app is a regular app (name and menus top left, Dock, ⌘Tab) while the main, settings or onboarding window is visible, and an accessory otherwise (`AppDelegate.updateActivationPolicy`). The notes window doesn't count: it is a non-activating panel, so clicking it never takes focus from the meeting app or brings our other windows forward; it becomes key only for its text fields. Opening the app by hand shows the main window (not when started as a login item); the Dock icon brings back whichever windows are open (the main window only when none is); quitting while a meeting with lines is being recorded asks first; exports are a sheet on the window they were asked from. The settings window remembers its frame and last tab (`settingsSection`). Menus: app (关于 with links to the site, GitHub and issues — `AboutPanel`; 检查更新…, which becomes 安装 x.y.z once one is found), 纪要, 显示 (display mode, ⌘1–⌘3 sizes, 始终置顶), 编辑 (standard responder-chain actions, so ⌘V works in fields; ⌘F search), 窗口, 帮助 (新手引导, 知了网站, 反馈问题… → GitHub `issues/new`).
- Updates (`UpdateChecker`, `Updater`, `Updates`, `UpdateViews`; ported from cameo): once a day (release builds; a dev build only with a test feed) `api.github.com/repos/wquguru/cicada/releases/latest`; a newer tag puts an orange dot on the menu bar glyph (`BrandImage.menuBar(badge:)`, no longer a template image then) and a strip in the panel. Installing asks first when a meeting with lines is live and ends it (`Updates.install`; quitting then doesn't ask again, `Updates.installing`, or the swap script would wait for a quit the user cancelled), downloads `Cicada-*-macOS-AppleSilicon.zip`, checks it against `checksums.txt`, the bundle id, the version and `codesign --verify`, and a shell script swaps the bundle after the app quits and reopens it. Ad-hoc signing with the bundle id as designated requirement keeps the TCC permissions across the swap. Not in place (DMG, App Translocation, unwritable folder) or any failure: the reason in the panel and the release page opens. Silent while the repository is private (the API answers 404). `CICADA_UPDATE_FEED=<url>` or the `updateFeed:` debug command points it at a fake release JSON (`file://` assets work). 登录时打开 is `SMAppService.mainApp` (`LoginItem`), state read from the system, never stored.
- Meeting records: one folder per meeting, `session.json` + `system.m4a` (+ `mic.m4a`; recorded as ADTS `system.aac` / `mic.aac`, which survive a crash, and rewrapped to .m4a without re-encoding at the end or at the next launch, `AudioFileWriter.finish`); sentences heard before auto-detection confirms the language are held and recorded once it does (dropped on a switch, which replays them); empty meetings are dropped; export to Markdown, Word (`.docx` via `NSAttributedString`, both starting with the notes) and SRT. Speaker labels are only "对方" (system audio) and "你" (microphone): no diarization yet.
- Shortcuts (`Shortcuts.swift`): talk and subtitle-bar toggle are recorded in settings (`ShortcutField`). A combination must include ⌃ or ⌘ (⌥/⇧ alone types characters; bare F keys are brightness/volume), must not be a system shortcut (`CopySymbolicHotKeys`) or held by another app (Carbon refuses to register it).
- Nothing the user does needs the Terminal. When a feature request fits none of the above, push back before adding UI.

## Design

- Source of truth: the Design canvases in claude.ai (logo directions, onboarding, auto show/hide) and the app itself.
- Look: light grey ground `#F3F4F6`/`#F6F7F9`, white cards, ink `#15171C`, one accent orange `#E8552B` for "live" (dots, the speaking line, the icon). Text greys `#5A5F6B` / `#6B7080` (they pass 4.5:1 on white).
- Logo B (design: claude.ai/artifact/96R6Md276c3jAS4Mk4Ustn): a cicada's dark eyes and white wings peeking over a white subtitle card that leans 5° and bleeds off the bottom right, on an orange gradient squircle. The geometry (100-unit design space) is in three places kept in step: `CicadaLogo` in `Onboarding.swift` (the in-app `BrandMark` and the one-colour menu bar glyph `BrandImage.menuBar` with a whole card, 40% when paused), its copy in `Sources/LiveSubsIcon` (the app icon) and `site/icon.svg`. After changing it: `scripts/site-images.sh` (site `icon.png`, `og.png`) and `docs/icon.png` (the README's, the app icon's 256 px render).
- Copy is Chinese, short: one line of grey helper text at most. The UI also ships in English (`Localization.swift`): the Chinese source text is the key and `Resources/{en,ja,ko}.lproj/Localizable.strings` hold English, Japanese and Korean (English plurals in `en.lproj/Localizable.stringsdict`). SwiftUI literals (`Text`, `Button`, `.help` …) localize by themselves; every other UI string goes through `L("…")` (menus, alerts, status text, `String` parameters such as `SoftButton`/`SettingsRow`). Never `L()` prompts, `debugLog` lines or anything stored (session titles, speaker ids). Dates use `dateText(_, template)`. After changing UI text run `python3 scripts/strings.py` (lists keys missing in any language and values whose format specifiers differ from the key; `--write` adds them as TODO and regenerates the `zh-Hans` identity table, needed because the development region is English). English runs wider: check the panel, sidebars and segmented pickers in both languages.

## Layout

- `Package.swift`: SwiftPM, macOS 26+, Swift 5 language mode, no dependencies.
- `Sources/LiveSubs`: the app. Engine files are UI-free: `SystemAudioTap`, `AudioRouter` (resample, feed, ring buffer, recording), `LanguageDetector`, `ListenEngine`, `SpeakEngine`, `Shortcuts` (Carbon `HotKey`, right-⌥ `RightOptionKey`), `Ling` (Keychain key + client), `Notes` (model + engine), `Translator`, `VirtualMic`, `SessionStore` (+ exports). UI: `Overlay` (subtitle bar), `Views` (panel, main window), `SettingsWindow` (settings + the virtual mic checklist), `AISettings`, `NotesWindow` + `NotesViews` (live notes window; notes and transcript views shared with the main window), `Onboarding` (+ sample player, brand mark), `AppMenu` (the menus top left), `AboutPanel`, `UpdateViews` (panel strip, 通用 rows), `AppModel` (wiring, status item, windows, activation policy, debug control, `@main`). `DMGBackground` draws the installer background; `DevBuild` tells dev from release.
- `Sources/LiveSubsIcon`: CLI that renders the icon set (`--dev` adds the DEV band).
- `Resources/`: `Info.plist`, `sample/` (the 7 s onboarding clip, made by `scripts/make-sample.sh`), `dmg/DS_Store` (installer window layout).
- `scripts/build.sh`: builds `build/Cicada.app` (executable `Cicada`; the SwiftPM product and the source folder are still `LiveSubs`). Shown as 知了 on Chinese systems and Cicada elsewhere (`Resources/*.lproj/InfoPlist.strings`). Without `RELEASE=1` it is a **dev build**: "知了 Dev" / "Cicada Dev", bundle id `com.wquguru.cicada.dev`, `LiveSubsDev` = `branch @ commit[+]` in Info.plist; "DEV" beside the menu bar glyph, a DEV badge and the stamp in the panel, a DEV band on the icon, its own settings, permissions, `~/Library/Application Support/LiveSubs Dev` and log `/tmp/livesubs-dev-debug.log`. Both builds are signed ad hoc with a fixed designated requirement (the bundle id) so rebuilding keeps the system-audio and microphone permissions. Don't change the release bundle id `com.wquguru.cicada`: permissions are tied to it.
- `scripts/package.sh`: `RELEASE=1` build (refuses any other bundle id) → `Cicada-<version>-macOS-AppleSilicon.dmg` / `.zip` + `checksums.txt`. The DMG background is drawn by the app (`LiveSubs --render-dmg-background out.png <scale>`); the window layout is `Resources/dmg/DS_Store`, made by Finder via `scripts/dmg-template.sh` — rerun it after changing the window, icon positions or background, and keep `DMGBackground.swift` in step.
- `site/`: the website (GitHub Pages, Chinese first): `index.html` and `changelog.html` are templates sharing `header.html` / `footer.html` and `style.css`; `changelog.json` is the Chinese changelog the site shows (newest first, `"date": null` = not released yet; keep it in step with `CHANGELOG.md`). `scripts/site.py` builds `build/site/` (pages, `feed.xml`, `sitemap.xml`, `robots.txt`; `SITE_URL` sets the address); `.github/workflows/pages.yml` deploys it (skipped while the repo is private). `og.png` and `icon.png` are rendered by `scripts/site-images.sh` (Chrome) from `scripts/site-og.html` and `site/icon.svg`, and committed. Phones get no download: a "发到我的 Mac" button shares or copies the link.
- `tools/`: test helpers (remote control, synthetic mouse/keys, window capture, transcription check); see `tools/README.md`.

## Commands

```bash
swift build                          # debug build
scripts/test.sh                      # unit tests (Swift Testing; adds the CLT framework paths)
scripts/build.sh && open build/Cicada.app            # dev build (知了 Dev)
RELEASE=1 scripts/build.sh           # release build (com.wquguru.cicada)
scripts/package.sh                   # DMG + zip + checksums in build/
scripts/make-sample.sh               # regenerate the onboarding sample clip
python3 scripts/site.py && python3 -m http.server -d build/site   # website preview
```

Diagnostics (`Diagnostics.swift`, design: claude.ai/artifact/GHGzgN1sCodGfa17ZXLCa7): a "诊断" switch at the bottom left of the settings sidebar, beside the version (`diagnostics`, off by default; on in dev builds); switching it on adds a "诊断" tab below the others. It records only timings and counts, never transcript text: per heard sentence last new words → final transcript ("识别定稿") and final → translation, with Ling queue time, the provider that answered and why earlier ones fell through (`TranslateTrace`); per speak-back press release → transcript → translation → voice done; every Ling request (priority, queue, duration, outcome, tokens). Lines go to `metrics.jsonl` in the meeting folder (`type` = `sentence` / `ling`). The tab shows p50/p95, the provider split, fallback reasons, Ling rate and the last sentences as bars, and copies a plain-text report. It is separate from `debug`: the switch never enables transcript logging or the debug notification. Not done yet: the latency line under the subtitle bar and the health line in the panel.

Debug control: dev builds always accept commands on the distributed notification `com.wquguru.cicada.debug` (release builds only with `defaults write com.wquguru.cicada debug -bool true`, which also logs transcript text). Send them with `tools/lsctl` (`start`, `stop`, `open`, `panel`, `onboarding:<step>`, `samplePlay`, `speakFile:<audio>`, `settings:<overlay|speak|records|ai|diagnostics>`, `diagnostics:<on|off>`, `diagReport`, `micTest`, `micNext`, `talkKey:<right|keyCode:mods>`, `toggleKey:<keyCode:mods>`, `shortcuts`, `aiKeyFile:<path>` (key from a 0600 file, never through the log), `aiCheck`, `aiRemove`, `aiState`, `lingSimulate:<429|hijack|timeout|off>`, `voice:<lang>[=<id>]`, `voicePreview:<lang>=<id>`, `voiceCloneFile:<wav>`, `display:<notes|bar|none>`, `subtitles:<both|translation|original>`, `meetingSubtitles:<…>`, `notesLang:<mine|source>`, `meetingNotesLang:<…>`, `notesRegenerate:<id>=<mine|source>`, `settings:language`, `notesWindow[:x,y,w,h]`, `notesClose` (its close button), `closeWindow:<main|settings|onboarding>`, `notesFrame`, `notesNow`, `notesState`, `notesShow:<id>`, `notesReplay:<id>`, `notesRender:<png>`, `notesCapturable`, `windowsRender:<dir>` (every visible window as drawn), `settingsRender:<section>=<png>` (one settings page in full), `mainShow:<id>[,transcript]`, `mainRender:<png>` (the main window, plus the shown meeting's whole notes page as `<png>.notes.png`), `place:x,y,w,font`, `frame`, `overlayState`, `export:<dir>`, `updateFeed:<url>`, `updateCheck`, `updateInstall`, `updateState`, `loginItem[:on|off]`, `about` …).

Release: `scripts/release.sh <x.y.z>` (clean `main`, a `## x.y.z — <today>` section in `CHANGELOG.md`) bumps `Resources/Info.plist`, commits, tags `v<x.y.z>` and pushes; `.github/workflows/release.yml` (runner `macos-26`) builds the tag, checks it matches Info.plist and publishes the DMG, zip and checksums with notes from `scripts/release_notes.sh`. `build.yml` runs on pull requests and on demand only: macOS minutes are expensive for a private repo.

Only Command Line Tools are required (no Xcode project). Do not add an `.xcodeproj`.

## Verifying changes

Run the app and check the behaviour, not just the build. For the English UI: `defaults write com.wquguru.cicada.dev AppleLanguages -array en`, relaunch, and `defaults delete com.wquguru.cicada.dev AppleLanguages` afterwards. The pattern used so far: dev build, `tools/lsctl` to drive it, `afplay Resources/sample/sample.m4a` (or `say -o` clips) as the "someone talking" input, read `/tmp/livesubs-dev-debug.log`, screenshot windows with `screencapture -l <id>` (`tools/winall`). Synthetic mouse/key events (`tools/mouse`, `tools/key`, `tools/toggle-key`) need the terminal to have Accessibility access. The notes window is excluded from screen capture: send `notesCapturable` before `screencapture -l`, or `notesRender:<png>` for the whole notes column. Ling tests need a key: `aiKeyFile:` a 0600 file in the scratchpad, deleted right after. Synthetic keys reach every app: another app's launcher may take ⌥ Space. The real microphone, the BlackHole install (password), granting Input Monitoring and a Mac without permissions need a person.

Unit tests (`Tests/LiveSubsTests`, `@testable import LiveSubs`, run with `scripts/test.sh`) cover the pure parts: version compare and checksum lookup, language-code mapping, detection scoring, SRT/Markdown export. Add a test when changing one of those. To try an update end to end: build with a bumped `CFBundleShortVersionString`, `ditto -c -k --keepParent build/Cicada.app Cicada-<v>-macOS-AppleSilicon.zip`, `shasum -a 256` it into `checksums.txt`, write a release JSON with `file://` asset URLs, run a copy of the older dev build from the scratchpad (not `build/`), then `updateFeed:file://…` and `updateInstall`.

## Conventions

- Keep files small and single-purpose; match the existing naming and comment density (comments say why).
- UI and engine state are `@MainActor`; audio callbacks never touch app state directly (they hand buffers to `AudioRouter`'s queue).
- No third-party dependencies; system frameworks only.
- User data: `~/Library/Application Support/LiveSubs/Sessions` and `UserDefaults` (`sourceMode`, `target`, `speakEnabled`, `speakFrom`, `speakTo`, `speakOutput`, `recordAudio`, `overlayAuto`, `overlayHideAfter`, `overlay.<screen>`, `lastDetected`, `onboarded`, `talkKey`, `toggleKey` as `keyCode:carbonModifiers`, `displayMode`, `subtitles` (both/translation/original: "original" translates nothing), `notesLanguage` (mine = `AppSettings.myLanguage`, source = the meeting's most heard language), `aiModel`, `speakVoices`, `notesOnTop`, `diagnostics`, `settingsSection`) and the Ling key file (`ling-api-key`).
- Add a line to `CHANGELOG.md` with every user-visible change. Keep `README.md` and `README.zh-CN.md` in step.
- Commit in coherent batches with a short imperative subject.
